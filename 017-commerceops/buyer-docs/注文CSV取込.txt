CommerceOps — EC受注・ピッキング・梱包・出荷・返品管理
操作説明書: 注文CSV取込

対応バージョン: 1.0.0
作成日: 2026-09-30


【この説明書について】
  EC サイトやモールから出力した注文の CSV ファイルを、CommerceOps に
  取り込む方法を説明します。

  ・CommerceOps は、EC サイト・モール・カートと自動では接続しません。
    注文は CSV ファイルの取込で登録します
    （電話注文などは「注文」画面の「手動で注文作成」でも登録できます）。
  ・各社の CSV の形式を自動で見分けることもしません。
    「Import Profile」という設定で、CSV の列と CommerceOps の項目を
    対応付けてから取り込みます。
  ・画面名・ボタン名は「」で示します。
  ・R19 などの番号は、製品に含まれる自動テストの番号です。
    その動作がテストで確認されていることを表します。


■ 1. 全体の流れ

  1. 販売チャネルを登録する（最初に 1 回）
  2. チャネルごとに Import Profile を作る
     （最初に 1 回。CSV の形式が変わったら修正）
  3. 「注文取込」で CSV を選び、プレビューする
  4. 注文ごとの判定結果を確認する
  5. 「確定する」で注文を作成する
  6. 「要確認」になった注文を直す

  確定するまで注文は作成されません。
  プレビューだけなら、何度でもやり直せます。


■ 2. 用語

  販売チャネル
    注文が入ってくる経路です（自社EC、モール、卸、電話など）。
  Import Profile（インポート プロファイル）
    CSV の読み方の設定です。文字コード、区切り文字、日付の書式、
    列と項目の対応（列マッピング）などをまとめたものです。
  外部注文番号
    EC サイト側の注文番号です。取込では CSV の「注文番号」の列などから読みます。
  注文番号
    CommerceOps が付ける番号です（SO-000001 の形式）。
  取込番号
    取込 1 回ごとの番号です（IMP-000001 の形式）。
  要確認
    注文として登録したものの、住所の不備や未登録の SKU があるため、
    そのままでは引当・出荷作業に進めない状態です。
  引当
    在庫を注文のために確保することです（「在庫引当.txt」を参照）。


■ 3. 事前準備（最初に 1 回）

【3-1. 販売チャネルを登録する】
  必要な権限: Owner（オーナー）

  1. メニュー「設定」を開き、タブ「販売チャネル」を選びます。
  2. 「チャネルを追加」を押します。
  3. 名称、コード（英数字）、種類、取込方法を入力して「保存」を押します。
     ・コード: 英数字と「-」「_」で 16 文字以内。組織の中で重複できません。
     ・種類（Shopify、Amazon、楽天、BASE、STORES、自社EC、卸、手動、その他）は
       表示・集計用のラベルです。種類によって CSV の読み方は変わりません。
     ・取込方法: CSV で取り込むチャネルは「CSV」を選びます。

【3-2. Import Profile を作る】
  必要な権限: Owner（オーナー）

  1. 「設定」→ タブ「Import Profile」→「新規作成」を押します。
     （「販売チャネル」の一覧にある「Import Profile」ボタンからも開けます）
  2. 「販売チャネル」と「プロファイル名」を入力します。
  3. 基本設定（4-1）を、取り込む CSV に合わせます。
  4. 「サンプル CSV で確認」で実際の CSV を選び、列の並びを確認します（4-6）。
  5. 「列マッピング」で、項目ごとに取得方法を設定します（4-2）。
  6. 「変換結果を確認」を押し、先頭 20 行が正しく読めるか確認します。
  7. 「保存」を押します。

  ・1 つのチャネルに複数の Import Profile を作れます
    （例: 形式の違う 2 種類の CSV を扱う場合）。
  ・保存するたびに版（v1、v2 …）が上がります。
    取込ごとに、使った Profile の版が記録されます。
  ・「有効」のチェックを外した Profile は、取込の画面に表示されません。
  ・付属の「注文CSVテンプレート（標準）.csv」を使う場合は、新規作成の画面で
    「標準テンプレートを適用」を押し、他の設定は初期値のまま保存すれば使えます
    （「CSVテンプレート」フォルダの「CSVテンプレートの説明.txt」を参照）。


■ 4. Import Profile の設定項目

【4-1. 基本設定】
  文字コード
    「UTF-8（BOM 有無どちらも可）」または「Shift_JIS（CP932）」。
    自動では判定しません。詳しくは 6 章を参照してください。
  区切り文字
    「カンマ（CSV）」または「タブ（TSV）」。
  先頭の読み飛ばし行数
    0〜20 行。見出し行の前にタイトル行などがある CSV で使います。
  ヘッダー行
    「あり（列名で指定）」または「なし（列番号で指定）」。
  日付書式、日時のタイムゾーン
    4-5 を参照してください。
  検証エラーのある注文
    ・「「要確認」として取り込む（住所不備・未登録SKU等）」（初期値）
      住所の不備や未登録の SKU があっても注文を作成し、状態を「要確認」にします。
    ・「取り込まない」
      そのような注文は「エラー」として取り込みません。

【4-2. 列マッピング（列の対応付け）】
  「列マッピング」の表で、CommerceOps の項目ごとに「取得方法」を選びます。

  使わない
    その項目は CSV から読みません。
  列名
    見出し行の列名で指定します（ヘッダー行「あり」のときだけ）。
    例: 注文番号
  列番号
    左から何番目の列かで指定します。左端の列が 0 です
    （1 列目 = 0、2 列目 = 1 …）。「サンプル CSV で確認」の表では、
    列名の下に #0、#1 … と表示されます。
  複数列を連結
    複数の列をつないで 1 つの値にします（ヘッダー行「あり」のときだけ）。
    列名をカンマ区切りで最大 5 つと、つなぐときの区切り
    （初期値は半角スペース）を指定します。空欄の列は飛ばしてつなぎます。
    例: 住所1,住所2
  固定値
    CSV の中身に関係なく、すべての注文に同じ値を入れます。
    例: 配送方法をすべて「宅配便」にする

  項目名の下の印
    「必須」   列マッピングがないと Profile を保存できません。
               値が空または不正な注文は「エラー」になり、取り込まれません。
    「要確認」 値が空または不正だと、注文は「要確認」になります
               （「検証エラーのある注文」が「取り込まない」のときは「エラー」）。
    印なし     任意の項目です。

【4-3. 取り込める項目】
  （必須・要確認は 4-2 の印の意味です）

  注文ごとの項目
    注文番号（必須）
      外部注文番号。100 文字まで。
    注文日時（必須）
      日付書式（4-5）で読みます。
    購入者名
      100 文字まで。
    購入者メール
      形式が正しくない場合も取り込み、注意を表示します。
    購入者電話
      数字・ハイフン・「+」以外の文字は取り除いて保存します。
      数字が 9〜15 桁でない場合は注意を表示します。
    チャネル顧客ID
      モールの会員番号など。
    送付先氏名（要確認）
      100 文字まで。
    郵便番号（要確認）
      7 桁。ハイフンの有無、全角数字はどちらでも可。
      「123-4567」の形で保存します。
    都道府県
      空欄で、住所1 が都道府県名で始まっている場合は、自動で分けて保存します。
    市区町村
    住所1（要確認）
      番地まで。200 文字まで。
    住所2（建物名等）
    送付先電話
    配送方法
      50 文字まで。自由な文字（例: 宅配便）。
    備考
      1,000 文字を超えた分は切り詰め、注意を表示します。
    優先度(0-9)
      0〜9 の整数。大きいほど優先され、引当・Wave の並び順に使います。
    キャンセルフラグ
      注文が取り消されたことを示す列（7 章「取消候補」、4-4 の説明）。

  明細（商品）ごとの項目
    SKU（必須）
      64 文字まで。商品マスターの SKU と完全に一致するものとして扱います
      （大文字・小文字、全角・半角も区別します）。
      商品マスターにない SKU の注文は「要確認」になります。
    商品名
      空欄の場合は、商品マスターの商品名を使います。
    数量（必須）
      1〜100,000 の整数。「1,200」のようなカンマや全角数字も読めます。
    単価
      小数 2 桁まで。「¥」「￥」「円」「,」は自動で取り除きます。
      読めない値は注意を表示し、単価なしで取り込みます。
    バリエーション
      空欄の場合は、商品マスターのバリエーションを使います。
    明細ID

  ・すべての項目で、値の前後の空白は自動で取り除きます。

【4-4. 変換（使える操作）】
  列マッピングの「変換」欄にある「＋ 変換を追加」から追加します。
  1 つの項目に最大 10 個まで設定でき、上から順に適用されます。
  安全のため、正規表現やプログラム（式）は使えません。

    前後の空白を除去
    全角英数を半角に
    大文字に
    小文字に
    数字以外を除去
    指定文字を除去
      例: 「¥,円」と指定すると ¥・カンマ・円 を取り除きます。
    文字列を置換（完全一致の文字列）
      書いた文字列そのものを置き換えます（ワイルドカードは使えません）。
    空欄のときの値
      例: 配送方法が空欄なら「宅配便」にする
    指定文字数で切り詰め
    値の対応表
      「元=先」をカンマ区切りで入力します。
      例: ネコポス=nekopos, 宅急便=yamato
      表にない値は、そのまま残ります。

  キャンセルフラグの値
    次の値を「取消」と判定します。
      1 / true / yes / y / on / cancel / cancelled / canceled /
      キャンセル / 取消 / 取り消し / はい
    次の値を「取消ではない」と判定します。
      空欄 / 0 / false / no / n / off / いいえ / 有効 / normal
    これ以外の値（例: 「発送済」）は判定できません。その注文は「取消ではない」
    ものとして扱い、プレビューに注意を表示します。
    注文のステータス列を使う場合は「値の対応表」で、取消を表す値を true に、
    それ以外の値をすべて false に対応付けてください。
      例: キャンセル=true, 発送待ち=false, 発送済=false

【4-5. 日付書式とタイムゾーン】
  日付書式は、次の記号を組み合わせて指定します（大文字・小文字を区別します）。
    yyyy  年（4 桁）
    MM    月（2 桁）          M   月（1〜2 桁）
    dd    日（2 桁）          d   日（1〜2 桁）
    HH    時（2 桁、24 時間） H   時（1〜2 桁）
    mm    分（2 桁）
    ss    秒（2 桁）
  記号以外の文字（- / : 年 月 日 空白 など）は、そのとおりに一致させます。

  入力欄には次の候補が表示されます。
    yyyy-MM-dd HH:mm:ss    （初期値。例: 2026-09-30 14:05:00）
    yyyy/MM/dd HH:mm:ss    （例: 2026/09/30 14:05:00）
    yyyy/M/d H:mm          （例: 2026/9/30 14:05）
    yyyy/MM/dd             （例: 2026/09/30）
    yyyy-MM-dd             （例: 2026-09-30）
    yyyy年M月d日 H時mm分   （例: 2026年9月30日 14時05分）
    ISO                    （例: 2026-09-30T14:05:00+09:00）

  ・書式には yyyy（年）、M（月）、d（日）が必要です。
  ・2 月 30 日のような存在しない日付や、2000〜2100 年以外の日付は読めません。
  ・全角の数字は半角として読みます。
  ・時刻のない書式の場合は、その日の 0 時 0 分として扱います。

  日時のタイムゾーン
    CSV の日時が、どの地域の時刻で書かれているかを指定します。
    初期値は Asia/Tokyo（日本時間）です。海外の時刻の場合は
    America/New_York のような名前（IANA のタイムゾーン名）で指定します。
    夏時間も考慮して変換します。
    ISO 形式で「+09:00」「Z」などの時差が書かれた日時は、その時差を使います。

【4-6. サンプル CSV で確認する】
  Import Profile の画面の「サンプル CSV で確認」で CSV ファイルを選ぶと、
  次の内容を表示します。確認するだけで、保存も取込もしません。
    ・ファイル名、行数、列数、BOM の有無
    ・列名と列番号（#0、#1 …）。ヘッダー行なしの場合は「列1」「列2」…
    ・先頭 5 行の中身

  ボタン
    「列名から候補を反映」
      よく使われる列名（受注番号、お届け先氏名 など）から対応を推測して
      反映します。すでに設定した項目は変わりません。
      推測なので、必ず内容を確認してください。
    「標準テンプレートを適用」
      付属の注文CSVテンプレート（標準）用の対応に置き換えます。
      それまでの列マッピングは置き換わります。
    「変換結果を確認」
      今の設定（保存前でも可）で先頭 20 行を変換した結果を表示します。
      「問題」の欄に「取込不可」「要確認」「注意」が表示されます。
      CSV にない列を指定している場合は、その内容が上部に表示されます。

  ・文字化けしていないか、日付・金額・郵便番号が正しく読めているかも
    確認してください。
  ・文字コードを変えたときは、ファイルを選び直してください。


■ 5. 取込の手順

  必要な権限: Owner（オーナー）、Operations Manager（運用管理）

【ステップ 1: ファイルを選んでプレビューする】
  1. メニュー「注文取込」を開き、「新しい取込」を押します。
     （「注文」画面の「CSV 取込」からも開けます）
  2. 「Import Profile（チャネル）」を選びます。
  3. 「注文 CSV ファイル」で CSV ファイルを選びます。
     ファイルは最大 20MB、10 万行までです。大きい場合は分けてください。
  4. 「プレビュー」を押します。
     この時点では、まだ注文は作成されません。

【ステップ 2: 判定を確認する】
  プレビューが終わると「取込 IMP-000001」のような画面に変わります。
  ・上部の四角（タイル）: 判定（7 章）ごとの件数です。
    タイルを押すと、その判定の注文だけに絞り込めます。
  ・「確定すると 新規 ○ 件（○ 明細・合計数量 ○）を作成します」の案内が
    表示されます。「要確認」になる件数も表示されます。
  ・「注文ごとの判定」の表: 外部注文番号、判定、明細、送付先、
    行（CSV の行番号）、エラー / 注意 が表示されます。
    エラーは赤い文字、注意は茶色の文字です。「要確認:」で始まる注意は、
    その注文が「要確認」になる理由です。
  ・注文番号を読み取れない行があると、行番号付きで表示されます
    （その行は取り込まれません）。
  ・内容がおかしい場合は「取消」を押し、CSV または Import Profile を直して
    やり直します。

【ステップ 3: 確定する】
  1. 判定が「更新候補」の注文のうち、取込データで更新したいものだけ、
     「更新」の列にチェックを入れます。チェックしないものは更新しません。
  2. 「確定する」を押し、確認画面でもう一度「確定する」を押します。
  3. 「確定結果」に件数が表示され、表の「結果」の列に 1 件ずつの結果が出ます。
       作成 / 更新 / 重複スキップ / 更新見送り / 競合（例外登録） /
       取消候補（例外登録） / エラーのため未取込 / 取消済みのため未取込

  ・確定は 1 回でまとめて処理します。途中で失敗した場合はすべて取り消され、
    既存のデータは変わりません。
  ・確定するときに、既存の注文ともう一度照合します。プレビューの後で
    作業が進んだ注文は、確定時の状態で判定されます。
  ・確定は、プレビューしたときの内容で行います。プレビューの後で
    Import Profile を変えた場合は、もう一度プレビューしてください。
  ・プレビューから 24 時間を過ぎると確定できません（状態は「期限切れ」に
    なります）。もう一度プレビューしてください。
  ・「設定」→「組織・運用設定」の「CSV 取込の確定後に引当を自動実行する」が
    オンの場合は、新しい注文が 1 件以上作成されると、確定後に引当が始まります
    （「引当を開始しました」と表示されます）。初期値はオフです。


■ 6. 文字コードとファイルの形式

【対応している文字コード】
  ・UTF-8（BOM あり・なし どちらも可）
  ・Shift_JIS（CP932。「髙」「①」などの Windows の拡張文字も読めます）
  この 2 つ以外（EUC-JP、UTF-16 など）には対応していません。

  ・文字コードは自動で判定しません。Import Profile の「文字コード」で読みます。
  ・UTF-8 の Profile で UTF-8 ではないファイルを選ぶと、次のように表示されます。
      ファイルを UTF-8 として読み込めません。Shift_JIS（CP932）の可能性が
      あります。文字コードに「Shift_JIS」を指定して取り込み直してください
      （注文の取込では Import Profile の設定）。
    注文の取込では、Import Profile の「文字コード」を「Shift_JIS（CP932）」に
    変えて保存し、もう一度プレビューします。
  ・Shift_JIS の Profile で、UTF-8 の BOM が付いたファイルを選ぶと、次のように
    表示されます。
      UTF-8 の BOM が付いたファイルです。文字コードに「UTF-8」を指定して
      取り込み直してください（注文の取込では Import Profile の設定）。
    Import Profile の「文字コード」を「UTF-8（BOM 有無どちらも可）」に変えます。
  ・Excel で保存するときの目安（日本語版 Windows の場合）
      「CSV UTF-8（コンマ区切り）」で保存 → UTF-8（BOM 付き）
      「CSV（コンマ区切り）」で保存      → Shift_JIS

【CSV の書き方】
  ・一般的な CSV の決まり（RFC 4180）で読みます。カンマ・改行・ダブル
    クォート（"）を含む値は " で囲み、値の中の " は "" と 2 つ重ねます。
    囲みの閉じ忘れなどは「CSV の構文エラー（○行目付近）」と表示されます。
  ・空の行は読み飛ばします。
  ・1 行 = 1 明細（1 商品）です。複数の商品がある注文は、同じ注文番号で
    複数の行にします。同じ注文の行は、ファイルの中で離れていてもまとめます。
  ・同じ注文の行では、注文ごとの項目（注文日時・購入者・送付先・配送方法・
    備考など）を、すべての行で同じ値にしてください。行によって違うと、
    どちらが正しいかを決めずに「同じ注文の行で「○○」が異なります」の
    エラーになります。1 行目にだけ送付先が入り、2 行目以降が空欄の CSV も
    このエラーになります。
  ・上限: 1 ファイル 20MB、10 万行、200 列、1 つの値は 1 万文字まで。


■ 7. 判定結果の意味と対応

  プレビューでは、注文ごとに次のどれかに判定します。
  既存の注文との照合は、同じチャネルの中で、外部注文番号で行います。
  チャネルが違えば、同じ注文番号でも別の注文として扱います。

【新規】
  意味:   まだ登録されていない注文です。
  確定時: 注文を作成します。住所の不備や未登録の SKU がある場合は
          「要確認」の状態で作成します（9 章）。
  対応:   「エラー / 注意」の欄を確認してから確定します。

【重複（同一）】
  意味:   同じ注文がすでに登録されていて、内容もまったく同じです。
  確定時: 何もしません（二重に作成しません）。
  対応:   不要です。

【更新候補】
  意味:   同じ注文がすでに登録されていて、内容が違います。
          登録済みの注文は、まだ引当も出荷もされていません
          （状態が 取込済・要確認・引当待ち・保留 で、引当・出荷の数量が 0）。
          「判定」の欄に「変更: 送付先・明細」のように、変わった項目が
          表示されます（注文日時、購入者、送付先、配送方法、備考、優先度、明細）。
  確定時: 初期状態では更新しません（結果は「更新見送り」）。
          「更新」にチェックを入れた注文だけ、取込データで更新します。
          送付先が変わる場合は、変更前の内容が注文の「住所変更履歴」に残ります。
          明細は取込データの内容に置き換わり、もう一度検証されます。
  対応:   変わった内容が正しいか確認し、更新するものだけチェックします。

【競合】
  意味:   同じ注文がすでに登録されていて内容が違い、登録済みの注文の作業が
          進んでいます（一部でも引当・出荷が済んでいる、またはキャンセル済み）。
  確定時: 注文は変更しません。例外キューに「取込競合」（重要度 高）を登録します。
  対応:   例外キューで変わった内容を確認し、必要な修正を注文の画面で
          行います（「例外対応.txt」を参照）。

【取消候補】
  意味:   キャンセルフラグの列が「取消」を示しています。
  確定時: 自動ではキャンセルしません。
          登録済みの注文がある場合は、例外キューに「取込競合」
          （取消候補、重要度 高）を登録します。
          まだ登録されていない注文や、すでにキャンセル済みの注文は取り込みません
          （結果は「取消済みのため未取込」）。
  対応:   例外キューで確認し、キャンセルしてよい場合は注文の画面で
          「キャンセル」します（「在庫引当.txt」の 9 章を参照）。

【エラー】
  意味:   必須の項目が空・不正、同じ注文の行で内容が食い違う、などの問題が
          あります。「検証エラーのある注文」を「取り込まない」にしている場合は、
          住所の不備や未登録の SKU がある注文もここに入ります。
  確定時: その注文は取り込みません（他の注文の確定には影響しません）。
  対応:   「エラー / 注意」の欄の行番号と内容を見て CSV を直し、
          もう一度取り込みます。すでに取り込めた注文は「重複（同一）」になるので、
          同じ行が含まれていても二重にはなりません。
          ただし、中身がまったく同じファイルは取り込めません（8 章）。


■ 8. 二重取込・再取込の安全性

【同じファイルは二度取り込めません】
  確定済みの取込と中身がまったく同じファイルは、プレビューの時点で
  次のように表示され、取り込めません。
    このファイルは取込済みです（IMP-000001）。
    同じファイルを二重に取り込むことはできません
  ・ファイルの中身から計算した識別値（SHA-256）で照合するので、
    ファイル名を変えても同じファイルと判断します。
  ・照合は組織全体で行います。別のチャネルや別の Profile を選んでも取り込めません。
  ・「取消」した取込や「期限切れ」の取込は数えません。
    同じファイルで、もう一度プレビューできます。

【同じ注文を含む別のファイルでも、注文は重複しません（R19）】
  前回の CSV に新しい注文を追加したファイルや、行の順番を変えたファイルを
  取り込むと、取込済みの注文は「重複（同一）」として飛ばし、新しい注文だけを
  作成します。外部注文番号は、1 つのチャネルに 1 件しか登録できない
  しくみになっています。同じ注文を含む 2 つの取込を同時に確定しても、
  注文は 1 件しか作成されません。

【同じ注文番号で内容が違う場合も、黙って上書きしません（R20）】
  ・作業前の注文 → 「更新候補」。チェックを入れたものだけ更新します。
  ・作業が進んだ注文 → 「競合」。注文は変更せず、例外キューに登録します。
  どちらの場合も、確認しないまま内容が上書きされることはありません。


■ 9. 「要確認」の注文を直す

  「要確認」の注文は、引当・出荷作業の対象になりません。
  必要な権限: Owner、Operations Manager、Customer Support（顧客対応）

  見つけ方
    ・「注文」画面のタブ「要確認」
    ・「ホーム」のタイル「要確認（未検証）」
    ・「引当」画面のタイル「要確認（引当対象外）」
  注文の画面を開くと、上部の「要確認:」の欄に理由が表示されます。

【未登録の SKU（「未登録の SKU: ○○」）】
  方法 A: 商品を登録してから再検証する
    1. 「在庫・商品」→ タブ「商品」で、その SKU の商品を登録します
       （「商品を追加」または「CSV 取込」）。
    2. 注文の画面に戻り、「再検証（商品登録後など）」を押します。
       問題がなくなると「検証OK。引当待ちになりました」と表示されます。
    ・再検証は注文ごとに行います。

  方法 B: 登録済みの商品に対応付ける
    1. 理由の横にある「商品を対応付け」を押します。
    2. SKU・商品名で検索し、対象の商品の「これにする」を押します。
    ・取込時の SKU は注文にそのまま残り、指定した商品として引当・出荷します。
    ・対応付けたことは監査ログに記録されます。
    ・引当・出荷が始まった明細は、対応付けを変えられません。

【住所の不備】
  （送付先氏名がありません / 郵便番号がありません / 郵便番号の形式が不正です /
    住所がありません）
  1. 注文の画面で「住所変更」を押します。
  2. 「送付先を変更（出荷前のみ）」の画面で、氏名、郵便番号（7 桁）、
     住所1（番地まで）を入力します。
     都道府県は、住所1 の先頭に含めても自動で分けて保存します。
  3. 「変更理由（必須・履歴に残ります）」を入力し、「変更する」を押します。
  ・変更前の住所は「住所変更履歴」に残ります。
  ・住所の不備で例外キューに登録された「住所不備」の例外は、住所を直すと
    自動で解決します。
  ・住所変更ができるのは、出荷済みの荷物がない注文だけです。
    キャンセル済み・完了の注文も変更できません。
  ・梱包中または梱包済みの荷物がある場合は、「納品書・送り状を作り直して
    ください」と表示されます。

  他に問題がなくなると、注文の状態は「引当待ち」になり、引当の対象になります。


■ 10. 購入者・送付先は注文時の内容を保存します

  ・注文には、取込時点の購入者・送付先・商品名・単価をそのまま保存します。
  ・購入者メール（またはチャネル顧客ID）がある注文は、チャネルごとに
    顧客情報（顧客マスター）を作成します。すでにある顧客情報は、
    次の取込で上書きしません。
  ・顧客マスターの内容が後から変わっても、過去の注文の購入者・送付先は
    変わりません（R21）。注文の画面の「顧客マスター」の欄にも
    「注文時の内容を保存しています（顧客マスターを編集しても変わりません）」
    と表示されます。
  ・注文の送付先を変えるときは、注文ごとに「住所変更」を使います
    （出荷前のみ。変更の履歴が残ります）。
  ・出荷確定の時点の送付先は、荷物（出荷）の記録にも保存されます。


■ 11. 取込履歴

  メニュー「注文取込」を開くと、「注文取込（CSV）」の画面に、これまでの取込が
  新しい順に表示されます。
    取込番号 / チャネル / Profile / ファイル / 状態 / 注文（件数） /
    結果（新規・更新・重複・競合の件数） / 作成（日時と実行した人）
  状態の表示
    プレビュー中（未確定） / 確定済 / 取消 / 期限切れ
  取込番号を押すと、その取込の判定と結果を確認できます。

  ・注文の画面の「取込バッチ」から、その注文を作成した取込を開けます。
  ・例外の画面の「取込」の欄からも、関係する取込を開けます。
  ・プレビュー、確定、取消、取込による注文の更新は、監査ログにも記録されます
    （メニュー「監査ログ」。Owner、Operations Manager が閲覧できます）。


■ 12. 個人情報を含む一時データの自動削除

  プレビューのために一時保存した注文の内容（送付先・明細など）は、
  個人情報を含むため自動で削除します。
  ・確定・取消・期限切れから 7 日後に削除します
    （削除は 1 時間ごとの自動処理で行います）。
  ・プレビュー中のまま 24 時間たつと「期限切れ」になります。
  ・「取消」を押した取込は、その時点で削除します。
  ・削除した後も、取込番号・件数・判定結果・エラーの内容は取込履歴に残ります。
    「注文ごとの判定」の明細・送付先の欄は空欄になります。
  ・作成された注文そのものは削除されません。


■ 13. CSV を出力するときの数式対策（R25）

  CommerceOps から出力する CSV（注文・在庫・出荷・返品・例外・KPI・
  監査ログ）では、「=」「+」「-」「@」、タブ、改行（CR）で始まる文字の値の
  先頭に「'」を付けて出力します。Excel などで開いたときに、値が数式として
  実行されるのを防ぐためです（CSV インジェクション対策）。
  ・例: 備考が「=HYPERLINK(…)」の場合、CSV には「'=HYPERLINK(…)」と出力します。
  ・数量のマイナスなどの数値は、そのまま出力します。
  ・「CSV 出力」「在庫CSV出力」のボタンでは、文字コードを「UTF-8（BOM 付き）」
    または「Shift_JIS」から選べます。Excel で開く場合は UTF-8（BOM 付き）なら
    文字化けしません。「出荷」画面の「出荷予定 CSV」「出荷実績 CSV」は
    UTF-8（BOM 付き）で出力します。
  ・CSV を出力したことは、件数などが監査ログに記録されます。

■ 15. よくある表示と対処

  「Import Profile がありません。設定 → Import Profile で作成してください
    （Owner 権限）。」
    → 3 章の手順で作成します。

  「このファイルは取込済みです（IMP-○○○○○○）。…」
    → すでに確定済みのファイルです。取込履歴で結果を確認してください。

  「ファイルを UTF-8 として読み込めません。… 文字コードに「Shift_JIS」を指定して
    取り込み直してください（注文の取込では Import Profile の設定）。」
    → Import Profile の「文字コード」を「Shift_JIS（CP932）」にして保存し、
      もう一度プレビューします。

  「UTF-8 の BOM が付いたファイルです。文字コードに「UTF-8」を指定して
    取り込み直してください（注文の取込では Import Profile の設定）。」
    → Import Profile の「文字コード」を「UTF-8（BOM 有無どちらも可）」にします。

  「Shift_JIS として読み込めない文字があります。文字コードを確認してください。」
    → UTF-8 のファイルの可能性があります。文字コードを確認してください。

  「CSV の列が Import Profile と一致しません（プロファイルかファイルを確認
    してください）」
    → 下に「○○: 列「△△」がファイルにありません」と表示されます。
      CSV の列名か、Import Profile の列マッピングを合わせます。
      使わない列でも、Profile で指定している列は削除しないでください。

  「CSV の構文エラー（○行目付近）: …」
    → ダブルクォートの閉じ忘れなどがないか、その行を確認します。

  「注文日時「…」を書式 yyyy-MM-dd HH:mm:ss で解釈できません」
    → CSV の日時の形と、Import Profile の日付書式を合わせます。
      Excel で開いて保存すると、日時の形が変わることがあります
      （「CSVテンプレートの説明.txt」を参照）。

  「同じ注文の行で「○○」が異なります（行 …）」
    → 6 章「CSV の書き方」を参照してください。

  「プレビューから24時間以上経過しています。もう一度プレビューしてください」
    → 同じファイルで、もう一度プレビューします。

  「このプロファイルまたはチャネルは無効です」
    → 「設定」で Import Profile と販売チャネルを有効にします。

  「ファイルサイズが上限を超えています」
  「行数が多すぎます（上限 100,000 行）。ファイルを分割してください」
    → ファイルを分けて取り込みます。
