CommerceOps — EC受注・ピッキング・梱包・出荷・返品管理
初期設定ガイド


【この資料について】
CommerceOps を使い始めるまでの準備を、順番に説明します。
・第 1 部: サーバーを用意する（サーバーを担当する人・委託先向け）
・第 2 部: 画面での初期設定（Owner 向け）
・第 3 部: 最初の注文を流してみる
詳しい技術情報は docs/DEPLOY.md（デプロイ）、docs/OPERATIONS.md（運用）に
あります。


========================================================================
第 1 部　サーバーを用意する（サーバー担当者向け）
========================================================================

■ 1. 必要なもの

・Node.js 22.12 以上が動くサーバー、または Docker が動くサーバー
・PostgreSQL 16（データベース）
・写真を保存する永続ディスク（返品検品の写真、数 GB〜）
・インターネットに公開する場合は HTTPS（証明書）
・メール送信の設定は不要です（招待・パスワード再設定はリンクを本人に
  渡す方式です）。

料金の目安は docs/OPERATING_COSTS.md を参照してください
（契約前に各社の公式ページで最新の料金を確認してください）。


■ 2. 大切な約束（データベースのユーザー）

アプリが使うデータベースのユーザーには、特別な権限（SUPERUSER /
BYPASSRLS）を付けないでください。組織ごとのデータの分離が働かなく
なるためです。本番設定（NODE_ENV=production）では、そのようなユーザーで
接続するとアプリは起動しません。作り方は docs/DEPLOY.md の §2 にあります。


■ 3. 方法を選ぶ

【方法 A: Docker Compose（1 台のサーバーで動かす）】
1. 017-commerceops フォルダで、設定ファイルの見本をコピーします。
     cp deploy/compose.env.example .env
2. .env を開き、次を変更します（推測されにくい長い値にします）。
     POSTGRES_PASSWORD（データベース管理者のパスワード）
     APP_DB_PASSWORD（アプリ用のパスワード）
     APP_BASE_URL（利用者が開く URL。例: https://ops.example.com）
   試しに http://localhost で動かすだけなら COOKIE_SECURE=false にします。
3. 起動します。
     docker compose up -d --build
   初回はデータベースの準備とアプリのビルドで数分かかります。
4. 最初の Owner（全権限の管理者）を作ります。
     docker compose exec app node dist/scripts/create-owner.js --org "店名" --email owner@example.com --name "氏名"
   パスワードが 1 回だけ表示されます。控えてください。

【方法 B: Render（PaaS）】
・render.yaml（設定の例）を使って作成できます。Render 上での動作は
  開発時に確認していません（アカウント作成・課金が必要なため）。
  手順は docs/DEPLOY.md の §5 です。

【方法 C: サーバーに直接インストール】
・Node.js と PostgreSQL を用意し、npm ci → npm run build → node dist/index.js
  の順で起動します。手順は docs/DEPLOY.md の §6 です。


■ 4. 起動の確認

・ブラウザで APP_BASE_URL（または http://サーバー:3000）を開き、
  ログイン画面が出ることを確認します。
・監視には /readyz（データベースに届いているか）を使います。
・アプリはバックグラウンドの処理（自動引当・作業の担当期限の解除・
  データの保持期限・統計情報の更新）も同じプロセスで行います。
  処理を分ける場合は docs/DEPLOY.md を参照してください。


■ 5. バックアップを必ず設定する

・データベース全体のバックアップ（クラウドの自動バックアップ、
  または毎日の pg_dump）を、別の場所へ保管してください。
・組織ごとのバックアップ（画面の「設定 → バックアップ・復元」）も
  定期的に取り、復元の練習を一度行ってください（バックアップ復元.txt）。


========================================================================
第 2 部　画面での初期設定（Owner 向け）
========================================================================

■ 6. ログインとパスワード変更

1. 表示されたメールアドレスとパスワードでログインします。
2. 画面右上（ユーザー名の横。狭い画面ではメニューの下部）の「パスワード変更」で、自分だけが知るパスワードに変えます
   （10 文字以上）。


■ 7. 設定（メニュー「設定」）

次の順に設定すると迷いません。
1. 組織 … 組織名・タイムゾーン、引当の動き（一部引当を許すか、
   全量引当で自動的に出荷作業を作るか 等）、Pick の担当期限、
   出荷確定で追跡番号を必須にするか、既定の配送会社
2. 倉庫・ロケーション … 倉庫（例: 東京倉庫）と棚（例: A-01）。
   棚はまとめて登録できます。棚のバーコードラベルは印刷できます。
3. 販売チャネル … 自社サイト・モールなど、注文の入口ごとに 1 つ
4. Import Profile … チャネルごとの注文 CSV の読み方（列の対応付け）。
   CommerceOps の標準 CSV（CSVテンプレート/注文CSVテンプレート（標準）.csv）
   ならそのまま使えます（注文CSV取込.txt）。
5. ユーザー・権限 … 担当者を招待します。役割（Operations Manager /
   Picker / Packer / Customer Support）と担当倉庫を選び、表示された
   招待リンクを本人に渡します（ユーザーと権限.txt）。


■ 8. 商品と在庫（メニュー「在庫・商品」）

1. 商品を登録します（1 件ずつ、または商品 CSV でまとめて）。
   JAN などのバーコードを登録すると、ピッキング・梱包で読み取れます。
2. 入荷を登録して在庫を入れます（棚ごと。在庫 CSV でまとめても可）。
   詳しくは 在庫引当.txt。


========================================================================
第 3 部　最初の注文を流してみる
========================================================================

■ 9. 練習はサンプル組織で

・本番のデータを入れる前に、サンプル組織「Sample Commerce」で一通り
  試すことをおすすめします（サンプル業務説明.txt）。
  サーバー担当者が次のコマンドで作成します。
    docker compose exec app node dist/scripts/seed-sample.js --owner-email owner@example.com

■ 10. 1 日の流れ（本番）

1. 注文取込 … モールやカートから出力した CSV を取り込む
2. 引当 … 在庫を注文に割り当てる（「引当を実行」）
3. Wave・ピッキング … Wave を作り、スマホでピッキング（スマホPick.txt）
4. Packing Station … PC・iPad で 1 個ずつ scan して梱包（Packing Station.txt）
5. 出荷 … 配送会社のシステムで作った送り状の追跡番号を入れて出荷確定
   （出荷と分割発送.txt）
6. 返品・交換 … 受付 → 到着 → 検品（返品交換.txt）
7. 例外キュー … 欠品・住所不備・現物不足などの対応（例外対応.txt）

■ 11. 本番の前に

・スマホ・iPad の実機、ハンディスキャナ、プリンタでの確認を行って
  ください（スマホ・iPadで使う.txt、docs/RELEASE_CHECKLIST.md）。
・注意事項.txt を必ずお読みください。

■ 仕入・補充・棚卸（追加機能）
--------------------------------------------------
「在庫・商品」画面に次のタブが増えました（Owner / Operations Manager が使えます。棚卸の計数は Picker も可）。

(1) 仕入先 … 仕入先のコード・名称・リードタイムを登録します。
(2) 発注 … 「発注を作成」で下書きを作り、実際に発注したら「発注済みにする」を押します。
    商品が届いたら発注の画面で今回届いた数を入力し「入荷を登録」。何回かに分けて届いても登録できます（分納）。
    もう届かない分は「未入荷分を打ち切る」で締めます（理由を入力）。
(3) 補充 … 商品ごとに「安全在庫・発注点・目標在庫・発注単位」を設定すると、
    在庫・発注残・まだ引当できていない注文から、発注が必要な商品と推奨数を表示します。
    発注数を確認して「仕入先ごとに発注の下書きを作成」を押すと、発注の下書きができます。
(4) 棚卸 … ロケーションを選んで「棚卸を開始」。実際に数えた数を入力し、差異がある行は理由を入れて
    「差異確認へ」→「確定して在庫に反映」。数えている間に入荷や出荷で在庫が動いた場合は確定できないので、
    中止して数え直してください。
(5) 在庫履歴の「取消」 … 入荷・調整・移動を間違えて登録したときに、反対の記録を追加して打ち消します。
    元の記録と取消の両方が履歴に残ります。1つの記録は1回だけ取り消せます。
