CSVテンプレートの説明

対応バージョン: 1.0.0
作成日: 2026-09-30


■ 1. このフォルダのファイル

  注文CSVテンプレート（標準）.csv
    注文の取込に使います。メニュー「注文取込」。
  商品CSVテンプレート.csv
    商品の一括登録・更新に使います。
    「在庫・商品」→ タブ「商品」→「CSV 取込」。
  在庫CSVテンプレート.csv
    在庫の一括登録に使います。
    「在庫・商品」→ タブ「在庫」→「在庫CSV取込」。
  追跡番号CSVテンプレート.csv
    荷物に追跡番号をまとめて登録するときに使います。
    「出荷」→「追跡番号 CSV 取込」。

  ・商品と在庫の CSV 取込の画面にも、このフォルダのテンプレートの名前が
    案内されています。
  ・例として入っているデータは、すべて架空のものです（9 章）。
  ・操作の詳しい説明は「注文CSV取込.txt」「在庫引当.txt」も参照してください。


■ 2. すべてのテンプレートに共通の決まり

【2-1. 文字コードと改行】
  ・テンプレートは UTF-8（BOM 付き）、改行は CRLF で保存しています。
    BOM 付きなので、Excel で開いても文字化けしません。
  ・取り込めるファイルの文字コード
      注文 CSV      Import Profile の設定（UTF-8 または Shift_JIS）
      商品 CSV      取込の画面で UTF-8 / Shift_JIS を選びます
      在庫 CSV      UTF-8 のみ（画面から取り込む場合）
      追跡番号 CSV  取込の画面で UTF-8 / Shift_JIS を選びます
    UTF-8 は BOM あり・なしのどちらでも読めます。Shift_JIS は Windows の
    拡張文字（CP932）を含みます。
  ・区切りはカンマです（注文 CSV は、Import Profile でタブ区切りも選べます）。
  ・カンマ・改行・ダブルクォート（"）を含む値は " で囲み、値の中の " は ""
    と 2 つ重ねます（Excel で保存すると自動でそうなります）。
  ・空の行は読み飛ばします。

【2-2. 1 行目の見出しを変えないでください】
  CommerceOps は、1 行目の見出し（列名）で列を探します。
  ・見出しの行を消さないでください。
  ・列の順番は入れ替えても構いません。
  ・決まった見出し以外の列を追加しても、その列は読みません（無視します）。
  ・注文 CSV
      見出しは、Import Profile の列マッピングの「列名」と一致している必要が
      あります。見出しを変える場合は、Import Profile の列マッピングも同じ名前に
      変えてください。
      使わない列も削除せず、空欄のまま残してください。標準テンプレート用の
      Import Profile は 18 列すべてを指定しているため、列を 1 つでも消すと
      「CSV の列が Import Profile と一致しません」となり取り込めません。
  ・商品 CSV・在庫 CSV
      見出しは英字の決まった名前です（大文字・小文字は区別しません）。
      変えないでください。
  ・追跡番号 CSV
      決まった名前、または 6 章の別名を使います。

【2-3. Excel で編集するときの注意】
  CSV を Excel で開くと、Excel が値を数値や日付に自動で変換します。
  そのまま保存すると、元の値に戻らないことがあります。

  起きやすいこと
    ・先頭の 0 が消える
        例: 郵便番号 0600001 → 600001
        0 から始まる商品コード・SKU・電話番号も同じです。
    ・桁の多い数字が指数の形になる
        例: JAN コード 2000001000014 → 2E+12
        この形で保存すると、元の番号に戻せません。
        12 桁の追跡番号なども同じです。
    ・日付・時刻の形が変わる
        例: 2026-09-28 10:15:00 → 2026/9/28 10:15
    ・「1-2」のような値が日付（1月2日）に変わる

  防ぐ方法
    1. Excel の「データ」タブの「テキストまたは CSV から」で CSV を読み込み、
       表示された画面で「データ型の検出」を「データ型を検出しない」にしてから
       読み込みます。すべての列を文字のまま扱えます。
       （Excel のバージョンによって、画面や名前が異なることがあります）
    2. 新しく入力する列は、先に列の書式を「文字列」にしてから入力します。
       または、値の先頭に「'」（半角のアポストロフィ）を付けて入力します。
       この「'」は CSV には保存されません。
    3. 保存するときは、ファイルの種類で「CSV UTF-8（コンマ区切り）」を選びます。
       「CSV（コンマ区切り）」で保存すると Shift_JIS になります。その場合は
       取込のときに Shift_JIS を選んでください（在庫 CSV は、画面から Shift_JIS
       では取り込めません）。
    4. 保存したファイルをダブルクリックで開き直すと、Excel がまた変換します。
       中身はメモ帳などのテキストエディタで確認するのが確実です。
    5. 注文 CSV の日時の形が変わってしまった場合は、Import Profile の
       「日付書式」を実際の形（例: yyyy/M/d H:mm）に合わせる方法もあります。

  このテンプレートでは、郵便番号・電話番号・追跡番号をハイフン付きで
  書いています。ハイフンがあると、Excel が数値に変換しにくくなります。
  取込のときに、郵便番号は「123-4567」の形に、追跡番号はハイフンを
  取り除いた形に、自動で整えます。
  JAN コードなどのバーコードにはハイフンを入れられないため、上の 1.〜4.
  の方法で扱ってください。


■ 3. 注文CSVテンプレート（標準）.csv

【使う前の準備】（Owner）
  このテンプレート用の Import Profile を作ります。
  1. 「設定」→ タブ「販売チャネル」で、チャネルを登録します（まだの場合）。
  2. 「設定」→ タブ「Import Profile」→「新規作成」を押します。
  3. 「販売チャネル」と「プロファイル名」を入力します。
  4. 「標準テンプレートを適用」を押します
     （「サンプル CSV で確認」でファイルを選ばなくても押せます）。
  5. ほかの設定は初期値のまま「保存」を押します。
       文字コード: UTF-8 / 区切り文字: カンマ / 先頭の読み飛ばし行数: 0 /
       ヘッダー行: あり / 日付書式: yyyy-MM-dd HH:mm:ss /
       日時のタイムゾーン: Asia/Tokyo
  ・「サンプル CSV で確認」でこのテンプレートを選び、「変換結果を確認」を
    押すと、正しく読めることを確かめられます。

【書き方】
  ・1 行が 1 明細（1 商品）です。複数の商品がある注文は、同じ注文番号で
    行を分けます（例の SAMPLE-1001 は 2 行、SAMPLE-1003 は 3 行）。
  ・同じ注文の行では、「注文番号」から「備考」までの 14 列を、すべての行で
    同じ値にします。行によって違うと、その注文はエラーになります。

【列の説明】
  （必須 = 空欄・不正だと、その注文は取り込まれません
    要確認 = 空欄・不正だと、注文は「要確認」の状態で取り込まれます
    任意 = 空欄でも構いません）

  注文番号（必須）
    EC サイトの注文番号（外部注文番号）。100 文字まで。
    例: SAMPLE-1001
  注文日時（必須）
    yyyy-MM-dd HH:mm:ss の形。日本時間として読みます。
    例: 2026-09-28 10:15:00
  購入者名（任意）
    100 文字まで。
  購入者メール（任意）
    例: taro@example.invalid
    形式が正しくない場合も取り込み、注意を表示します。
  購入者電話（任意）
    例: 000-0000-0001
    数字が 9〜15 桁でない場合は、注意を表示します。
  送付先氏名（要確認）
    100 文字まで。
  郵便番号（要確認）
    7 桁。ハイフンの有無、全角数字はどちらでも可。
    例: 000-0001
  都道府県（任意）
    空欄で、住所1 が都道府県名で始まっている場合は、自動で分けて保存します。
  市区町村（任意）
  住所1（要確認）
    番地まで。200 文字まで。
  住所2（任意）
    建物名・部屋番号。
  送付先電話（任意）
  配送方法（任意）
    50 文字まで。自由な文字。例: 宅配便
  備考（任意）
    1,000 文字まで（超えた分は切り詰めます）。
  SKU（必須）
    商品マスターの SKU と同じ値（商品CSVテンプレートの sku）。64 文字まで。
    大文字・小文字、全角・半角も区別します。
    商品マスターにない SKU の注文は「要確認」になります。
  商品名（任意）
    200 文字まで。空欄の場合は、商品マスターの商品名を使います。
  数量（必須）
    1〜100,000 の整数。
  単価（任意）
    小数 2 桁まで。「,」「¥」「円」は自動で取り除きます。
    例: 1500（「1,500円」のようにカンマを含む場合は " で囲みます）

  ・標準の Import Profile では、バリエーション・優先度・キャンセルフラグ・
    明細ID・チャネル顧客ID は読みません。使う場合は、CSV に列を追加し、
    Import Profile の列マッピングも追加してください（「注文CSV取込.txt」4 章）。

【例の注文】
  SAMPLE-1001  2 商品の注文
  SAMPLE-1002  購入者と送付先が別の人（贈り物）。備考あり
  SAMPLE-1003  3 商品の注文。購入者電話は空欄
  SAMPLE-1004  配送方法「メール便」

【取り込み方】
  「注文取込」→「新しい取込」→「Import Profile（チャネル）」を選ぶ →
  「注文 CSV ファイル」を選ぶ →「プレビュー」→ 判定を確認 →「確定する」
  ・同じファイルは 1 回しか取り込めません。2 回目は「このファイルは取込済み
    です」と表示されます。


■ 4. 商品CSVテンプレート.csv

【列の説明】
  sku（必須）
    SKU（商品コード）。64 文字まで。同じファイルの中で重複できません。
    すでに登録されている SKU の行は、その商品を更新します。
    書いたとおりに登録します（全角・半角の変換はしません）。注文の取込では
    SKU を完全に一致するもので照合するため、EC サイト側と同じ表記にします。
  name（必須）
    商品名。200 文字まで。
  variant（任意）
    バリエーション（色・サイズなど）。100 文字まで。例: M、ホワイト
  group_code（任意）
    商品グループ。同じ商品の色・サイズ違いに同じ値を入れておくと、梱包の
    検品で別のバリエーションを読んだときに「別 variant」と警告できます。
    64 文字まで。例: SAMPLE-TSHIRT
  barcodes（任意）
    バーコード（JAN コード、社内コードなど）。複数あるときは「|」（半角の
    縦棒）で区切ります。1 商品 20 個まで、1 つ 128 文字まで。
    例: 2000001000021|TAG-TSHIRT-L
    全角の数字・英字で書いた場合は、半角にして登録します。
    種類（JAN/EAN、UPC-A など）は、チェックディジットを確かめて自動で
    判定します。
    1 つのバーコードは 1 つの SKU にしか登録できません（すでに他の SKU に
    登録済みのコードや、同じファイルで 2 つの SKU に入れたコードはエラー）。
  weight_g（任意）
    重さ（グラム）。0〜1,000,000 の整数（小数は不可）。例: 180
  image_url（任意）
    商品画像の URL。https:// で始まるものだけ登録できます。
    ピッキング・梱包・商品確認の画面に画像が表示されます。
    例の URL（example.invalid）は画像の表示されない架空のアドレスです。
    実際の画像の URL に置き換えるか、空欄にしてください。
    取り込む前に、URL のファイル名と手元の画像ファイルの名前が合っているかを
    「CommerceOps 商品画像チェック」で確認できます（商品画像チェック.txt）。
  active（任意）
    0 / false / no / 無効 のどれかなら「無効」、それ以外（空欄を含む）は
    「有効」になります。

【取り込み方】（Owner、Operations Manager）
  1. 「在庫・商品」→ タブ「商品」→「CSV 取込」を押します。
  2. 「ファイル」と「文字コード」を選びます。
  3. 「検証のみ」で確認し、「問題ありません（○行）」と表示されたら
     「取り込む」を押します。「取込完了: 新規 ○ / 更新 ○」と表示されます。

【注意】
  ・すべての行が正しい場合だけ登録します。1 行でもエラーがあると何も登録
    されず、行番号と内容が表示されます。
  ・「検証のみ」で確認するのは、書き方とファイル内の SKU の重複です。
    他の商品に登録済みのバーコードとの重複は「取り込む」のときに確認し、
    見つかった場合は何も登録されません。
  ・登録済みの商品を更新するとき、空欄の列（列そのものがない場合も）は、
    その項目を空にして上書きします。active が空欄だと「有効」になります。
    更新にも、すべての列を入れたファイルを使ってください。
  ・バーコードは追加だけ行います。CSV に書かなかったバーコードは削除されません
    （削除は商品の画面で行います）。
  ・例のバーコードは、実在の商品と重ならないように、店内用（インストア）の
    番号帯（先頭 20）で作った、チェックディジットの正しい 13 桁の番号です。
    実際の JAN コードに置き換えてください。
  ・Excel で開くと、JAN コードが「2E+12」のような形になり、そのまま保存すると
    番号が壊れます（2-3 を参照）。


■ 5. 在庫CSVテンプレート.csv

【列の説明】
  warehouse_code（必須）
    倉庫コード。「設定」→「倉庫・ロケーション」で登録した倉庫のコードと
    完全に一致させます。例: TKY
  location_code（必須）
    ロケーションのコード。その倉庫に登録済みのロケーション。
    例: A-01、DEFAULT
  sku（必須）
    登録済みの SKU。
  qty（必須）
    数量（整数）。「実数で上書き」では 0 以上、「加算」では 1 以上。

【使う前の準備】
  ・例では、倉庫 TKY と、ロケーション A-01・A-02・B-03・DEFAULT を使って
    います。倉庫を追加すると DEFAULT は自動で作られます。A-01 などは
    「設定」→「倉庫・ロケーション」→ 倉庫の「ロケーション」→
    「ロケーションを一括追加」で作るか、DEFAULT に書き換えてください。
  ・例の SKU を使う場合は、先に商品CSVテンプレートで商品を登録してください。

【取り込み方】（Owner、Operations Manager）
  1. 「在庫・商品」→ タブ「在庫」→「在庫CSV取込」を押します。
  2. 「ファイル」を選び、「方法」を選びます。
       「実数で上書き（初期在庫・棚卸結果）」
         そのロケーションの在庫数（OnHand）を qty の数にします。
       「加算（入荷）」
         そのロケーションの在庫数に qty を足します。
  3. 「検証のみ」で確認し、問題がなければ「反映する」を押します。

【注意】
  ・すべての行が正しい場合だけ反映します。1 行でもエラーがあると何も反映
    されません（「○件のエラー（反映していません）」）。
  ・「加算」で同じファイルを 2 回反映すると、2 回足されます。
  ・「実数で上書き」で、引当済み・調査中の数より少ない数にする行があると、
    反映の時点でエラーになり、何も反映されません（「検証のみ」ではこの確認を
    しません）。
  ・同じ倉庫・ロケーション・SKU の組み合わせは 1 行にしてください
    （「実数で上書き」では最後の行の数になり、「加算」ではすべて足されます）。
  ・画面から取り込めるのは UTF-8（BOM あり・なし）のファイルだけです。
  ・担当する倉庫が決められているユーザーの場合、担当外の倉庫の行はエラーに
    なります。
  ・「在庫CSV出力」で出力した CSV は列の形式が違うため、そのままでは
    取り込めません。


■ 6. 追跡番号CSVテンプレート.csv

  送り状の発行などで追跡番号（伝票番号）が決まった後、出荷前の荷物に
  まとめて登録するときに使います。出荷確定まで同時に行うこともできます。

【荷物の指定のしかた】（行ごとに、次のどちらか）
  ・出荷番号（SH-000001 の形）で指定する
  ・注文番号（SO-000001 の形）と箱番号で指定する
      この「注文番号」は CommerceOps の注文番号です。EC サイトの注文番号
      （外部注文番号）ではありません。
      その注文の出荷前の荷物が 1 つだけなら、箱番号は省略できます。
  出荷番号が入っている行は、出荷番号で荷物を探します。
  出荷番号・注文番号・箱番号は、「出荷」画面の一覧や、「出荷予定 CSV」で
  確認できます。

【列の説明】
  出荷番号
    荷物の出荷番号。注文番号で指定しない行では必須。
    別名: 荷物番号 / お客様管理番号 / shipment_number / shipment
  注文番号
    CommerceOps の注文番号。出荷番号が空欄の行で使います。
    別名: order_number / order
  箱番号
    1 以上の整数。注文番号で指定し、その注文に荷物が複数あるときに必要です。
    別名: 箱 / box_no / box
  配送会社（「既定の配送会社」を設定していない場合は必須）
    ヤマト運輸 / 佐川急便 / 日本郵便 / 西濃運輸 / 福山通運 / その他
    次の書き方も使えます。
      ヤマト、クロネコヤマト、クロネコ、宅急便、佐川、飛脚、郵便、ゆうパック、
      ゆうパケット、ゆうメール、西濃、カンガルー便、福山、
      yamato、sagawa、japanpost、seino、fukutsu、other
    「ヤマト運輸株式会社」のように社名を含む書き方も認識します。
    空欄の行には、「設定」→「組織・運用設定」の「出荷」にある
    「既定の配送会社」を使います（設定は Owner）。「既定の配送会社」が
    「指定しない」（初期値）の場合、空欄の行は「配送会社が指定されていません」
    のエラーになります。
    別名: 運送会社 / carrier
  追跡番号（必須）
    英数字 4〜40 文字。ハイフンと空白は取り除き、全角は半角に、英字は大文字に
    して保存します。例: 0000-0000-1001 → 000000001001
    別名: 伝票番号 / お問い合わせ番号 / 問合せ番号 / tracking_number / tracking
  出荷日（任意）
    例: 2026-09-30、2026/9/30、2026/09/30 15:00
    時刻を省略すると 12:00 になります。日時は組織のタイムゾーンで読みます。
    出荷確定まで行う場合の出荷日時になります。空欄なら、確定した時刻です。
    1 日以上先の日時は出荷確定できません（追跡番号だけ保存されます）。
    別名: 出荷日時 / 発送日 / shipped_at

  ・見出しの名前は、大文字・小文字、空白・「_」の違いを区別しません。

【例の 4 行】
  1 行目  出荷番号で指定。ヤマト運輸。出荷日あり
  2 行目  出荷番号で指定。佐川急便。出荷日時あり
  3 行目  注文番号と箱番号で指定。日本郵便。出荷日は空欄
  4 行目  注文番号だけで指定（出荷前の荷物が 1 つの場合）。
          「ゆうパック」（日本郵便として認識）。スラッシュ区切りの日付
  例の出荷番号・注文番号は、実際の番号に書き換えてから使ってください。

【取り込み方】（Owner、Operations Manager）
  1. 「出荷」→「追跡番号 CSV 取込」を押します。
  2. 「CSV ファイル」と「文字コード」を選びます。出荷確定も行う場合は
     「追跡番号を入れた荷物を出荷確定する」にチェックを入れます
     （最初からチェックが入っています）。
  3. 「検証する」を押し、行ごとの結果を確認します。
  4. 「取り込む（○ 件）」を押します。

【注意】
  ・結果の表示: 更新予定（検証時）・更新 / 出荷確定 / 変更なし / エラー
  ・エラーの行があっても、正しい行は取り込まれます（1 行ずつ処理します）。
  ・1 回に 5,000 行までです。
  ・出荷済みの荷物の追跡番号は、CSV では上書きしません（同じ番号なら
    「変更なし」）。訂正は荷物の画面で、理由を入力して行います。
  ・同じ配送会社の同じ追跡番号が、ファイルの中で重複している行や、別の荷物で
    すでに使われている行はエラーになります。「取り込む」を実行すると、
    例外キューに「追跡番号重複」が登録されます。
  ・出荷確定できなかった荷物（保留中の注文など）は、追跡番号だけ保存し、
    理由を表示します。
  ・出荷確定すると、在庫数が減ります（同じ荷物で二重には減りません）。


■ 7. はじめて試すときの順番（例のデータを使う場合）

  1. 「設定」→「倉庫・ロケーション」→「倉庫を追加」で、コード TKY の倉庫を
     作ります。
  2. その倉庫の「ロケーション」→「ロケーションを一括追加」に A-01、A-02、
     B-03 を 1 行ずつ入力して「追加」を押します。
  3. 商品CSVテンプレート.csv を取り込みます（5 商品）。
  4. 在庫CSVテンプレート.csv を「実数で上書き」で取り込みます。
  5. 販売チャネルと Import Profile を作ります（3 章の【使う前の準備】）。
  6. 注文CSVテンプレート（標準）.csv を取り込みます。
     4 件の注文が「引当待ち」で作成されます。
  7. 「引当」→「引当を実行」を押します。
     4 件とも全量が引当され、出荷作業（Wave待ち）が作られます。
  8. この後は「Wave・ピッキング」→「Packing Station」→「出荷」と進みます。
     追跡番号CSVテンプレート.csv は、出荷番号・注文番号を実際の番号に
     書き換えてから使います。

  ・登録した商品は削除できず（無効にはできます）、注文も削除はできません
    （キャンセルはできます）。例のデータは、本番で使う組織とは別の組織で
    試すことをおすすめします。システムの管理者がサンプル組織
    「Sample Commerce」を作成している場合は、そこでも試せます
    （倉庫 TKY、ロケーション A-01 など、販売チャネル「Web Store」と標準の
    Import Profile が登録済みなので、上の 1・2・5 は不要です）。


■ 8. よくある表示と対処

  共通（文字コード）
    「ファイルを UTF-8 として読み込めません。… 文字コードに「Shift_JIS」を
    指定して取り込み直してください（注文の取込では Import Profile の設定）。」
      → Shift_JIS で保存されたファイルです。商品・追跡番号の取込では画面の
        「文字コード」で「Shift_JIS」を選び、注文の取込では Import Profile の
        文字コードを変えます。在庫 CSV の取込画面では文字コードを選べないため、
        「CSV UTF-8（コンマ区切り）」などで UTF-8 として保存し直してください。
    「UTF-8 の BOM が付いたファイルです。文字コードに「UTF-8」を指定して
    取り込み直してください（注文の取込では Import Profile の設定）。」
      → 取込の画面の「文字コード」（注文の取込では Import Profile）で UTF-8 を
        選びます。
  注文 CSV
    「CSV の列が Import Profile と一致しません …」
      → 見出しを変えた、または列を消した可能性があります（2-2）。
    「注文日時「…」を書式 yyyy-MM-dd HH:mm:ss で解釈できません」
      → Excel で保存して日時の形が変わった可能性があります（2-3）。
    「未登録の SKU: …」（注文が「要確認」）
      → 先に商品を登録し、注文の画面で「再検証（商品登録後など）」を
        押します。
  商品 CSV
    「ヘッダーに sku と name の列が必要です（商品CSVテンプレートを使用して
    ください）」
      → 1 行目の見出しを確認します。
    「SKU … がファイル内で重複しています」
      → 同じ SKU の行を 1 行にします。
    「バーコード … は既に SKU … に登録されています」
      → そのバーコードは別の商品に登録済みです。
  在庫 CSV
    「ヘッダーに warehouse_code,location_code,sku,qty が必要です」
    「倉庫コード … がありません」「ロケーション … がありません」
    「SKU … がありません」「数量 … が不正です」
      → 表示された行を直します。倉庫・ロケーション・商品は先に登録します。
  追跡番号 CSV
    「ヘッダーに「追跡番号」と「出荷番号」（または「注文番号」）の列が必要です
    …」
      → 1 行目の見出しを確認します。
    「配送会社が指定されていません」
      → その行に配送会社を入れるか、「既定の配送会社」を設定します（6 章）。
    「注文 … に該当する荷物がありません」
      → EC サイトの注文番号ではなく、CommerceOps の注文番号（SO-）を使います。
    「注文 … には荷物が複数あります。出荷番号か箱番号を指定してください」
      → 出荷番号か箱番号を入れます。
    「… は出荷済みです。追跡番号の訂正は荷物の画面から理由を入力して
    行ってください」
      → 出荷済みの荷物は CSV で変更できません。


■ 9. 例のデータについて

  テンプレートの例は、すべて架空のデータです。
  ・氏名: 見本 太郎、架空 花子 などの架空の名前
  ・メールアドレス: 実在しないドメイン example.invalid
  ・電話番号: 000 から始まる、実在しない形の番号
  ・郵便番号: 000 から始まる、実在しない番号
  ・住所: 「架空区」「架空市」などの架空の地名
  ・バーコード: 店内用（インストア）の番号帯の番号
  ・追跡番号: 0000 から始まる架空の番号
  ・画像の URL: 実在しないドメイン example.invalid
  実際に使うときは、例の行を削除し、見出しの行は残したまま自社のデータを
  入力してください。
