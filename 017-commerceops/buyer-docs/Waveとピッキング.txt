CommerceOps — EC受注・ピッキング・梱包・出荷・返品管理
Wave とピッキング（PC での管理操作）


【この資料について】
倉庫の管理者（Owner / Operations Manager）が PC で行う、
次の操作を説明します。
・出荷作業（Fulfillment）の確認
・Wave の作成と Pick List の印刷
・作業の割り当て（担当の期限・解除を含む）
・Short（現物不足）の処理とピック実績の訂正
・Wave の取消と進捗の確認
スマホでのピッキング手順は「スマホPick.txt」、
梱包は「Packing Station.txt」、
出荷確定は「出荷と分割発送.txt」を参照してください。
文中の番号・商品・ロケーションはすべて架空の例です。


■ 1. 用語

・Fulfillment（出荷作業）
  1 つの注文を 1 つの倉庫から出荷するための作業の単位です。
  番号は「F-000123」の形式です。
  画面では「出荷作業」とも表示されます。
・Wave（ウェーブ）
  複数の出荷作業をまとめてピッキングする単位です。
  番号は「W-000012」の形式です。
・Pick タスク
  Wave の中で 1 人が担当するピッキング作業のまとまりです。
  番号は「PT-000034」の形式です。
・ロケーション
  商品を置く棚の番地です（例: A-01-03）。
・引当
  注文のために在庫を確保することです。
  どのロケーションから取るかも、引当の時点で決まります。
・Short（ショート）
  ピッキングのとき、棚に必要数がないこと（現物不足）です。
・担当（claim）
  タスクを誰が作業しているかを表します。
  1 つのタスクを担当できるのは 1 人だけです。
・scan
  バーコードを読み取ることです。


■ 2. 出荷作業（Fulfillment）

【出荷作業ができるタイミング】
・注文の全数量が引当されると、出荷作業が自動で作られます
  （初期設定）。
  設定 → 組織・運用設定 の「全量引当になった注文を自動で
  Fulfillment（出荷作業）にする」をオフにしている場合は、
  注文画面の「在庫引当」欄に「出荷作業を作成」ボタンが
  表示されるので、それを押して作ります。
・一部だけ引当できた注文は、注文画面の「在庫引当」欄の
  「揃った分を先行出荷」を押すと、引当済みの商品だけで
  出荷作業が作られます（「出荷と分割発送.txt」参照）。
・1 つの注文に出荷作業が複数できることがあります。
  例: 倉庫を分けて出荷する / 揃った分を先行出荷する /
      Short のあと別の倉庫へ再割当する / 交換品を送る

【出荷作業の状態】
状態は、必要数・ピック済・梱包済・出荷済などの数量から
システムが自動で決めます。手で状態を変える操作はありません。
・Wave待ち：Wave にまだ入っていない
・Wave投入済：Wave に入ったが、まだピック実績がない
・ピッキング中：ピック実績または Short がある
・ピック済：全数ピック済み（梱包待ち）
・梱包中：Packing Station で梱包している
・梱包済：梱包が完了し、出荷を待っている
・出荷済：全数量を出荷確定した
・キャンセル
このほか「保留」「Short」「交換」の印が付くことがあります。

【Fulfillment 画面】
メニュー「Fulfillment」で「Fulfillment（出荷作業）」画面が
開きます。
・絞り込み：「状態」「倉庫」「絞り込み」
  （なし / Short あり / 保留中 / 締切超過）
・一覧：出荷作業番号、注文、倉庫、状態、Wave、
  数量（ピック済み数）、期限
・期限を過ぎた未出荷の出荷作業は、期限が赤字で表示されます。
・Short がある出荷作業には「Short を解決」ボタンが出ます
  （7 章）。

【優先度と期限】
・優先度：注文画面の「優先度・備考」で、0（通常）〜9（最優先）
  を設定します。未出荷の出荷作業にも反映され、
  Wave 作成時の並び順と絞り込みに使われます。
・期限：出荷作業を作るときに、倉庫の「出荷締切時刻」
  （設定 → 倉庫・ロケーション）から自動で計算されます。
  締切時刻より前に作られた出荷作業は当日の締切、
  過ぎてから作られたものは翌日以降の締切が期限になります。

【保留との関係】
・保留中の注文の出荷作業は、Wave の候補に表示されません。
・Wave に入れた後で注文を保留にすることもできます
  （作業中の場合は確認が表示されます）。
  保留は、梱包の開始・scan・梱包完了と出荷確定を止めます。
  ピッキングの読取は止めないため、必要に応じて作業者に
  連絡してください。


■ 3. Wave を作成する

操作できる人：Owner / Operations Manager

1. メニュー「Wave・ピッキング」を開き、
   右上の「Wave を作成」を押します。
2. 「倉庫」を選びます。Wave は倉庫ごとに作ります。
3. 必要に応じて、条件で絞り込みます。
   ・「優先度（以上）」：指定なし / 1 以上 / 3 以上 /
     5 以上 / 9 以上
   ・「出荷期限（まで）」：指定した日時までに期限が来る
     出荷作業だけを表示します。
   ・配送方法：配送方法ごとの件数がボタンで表示されます。
     押すと、その配送方法だけに絞り込みます（複数選択可）。
     配送方法が空のものは「（未指定）」と表示されます。
4. 条件に合う出荷作業が一覧（プレビュー）に表示されます。
   並び順は、優先度の高い順 → 期限の早い順 →
   注文日の古い順です。
   最初はすべてにチェックが入っています。
   Wave に入れないものはチェックを外します。
   上に「対象 N 件 / N 個」と「（1 Wave の上限 N 件）」が
   表示されます。
5. 「Wave 名（任意）」に名前を入れます
   （例: 午前便 / 当日出荷）。
6. 「タスクの分け方」を選びます（4 章）。
7. 「Wave を作成（N 件）」を押します。
   作成すると、Wave の詳細画面に移ります。

【プレビューに表示される出荷作業】
・選んだ倉庫の「Wave待ち」で、保留中でなく、
  まだどの Wave にも入っていない出荷作業だけです。
・表示されるのは「1 Wave の上限」の件数までです。
  初期値は 100 件で、設定 → 組織・運用設定 の
  「1 Wave の最大 Fulfillment 数」で 1〜500 件に変更できます。
  上限を超えた分は、次の Wave の作成時に表示されます。

【対象は作成した時点で固定されます】
・Wave に入る出荷作業は、「Wave を作成」を押した時点で
  固定されます。作成した後に届いた注文や、
  後から Wave待ちになった出荷作業が、
  同じ Wave に追加されることはありません。
・1 つの出荷作業が 2 つの Wave に入ることはありません。
  プレビューを見ている間に、別の人が同じ出荷作業で
  Wave を作った場合、その出荷作業は除外され、完了時に
  「N 件は他で処理済みのため除外」と表示されます。
  すべて除外された場合は、プレビューをやり直すよう
  メッセージが表示されます。
・Wave を作成すると、出荷作業は「Wave投入済」になり、
  注文の状態も通常は「ピッキング中」に変わります。


■ 4. タスクの分け方

「タスクの分け方」で、Wave をいくつの Pick タスクに
分けるかを選びます。
・1 人で全部（1 タスク）
  Wave 全体を 1 つのタスクにします。
・ゾーンごと
  ロケーションの「ゾーン」ごとにタスクを分けます。
  ゾーンが未設定のロケーションは、1 つのタスクにまとまります。
  複数人でエリアを分担するときに使います。
・行数ごと
  「1 タスクの行数」（初期値 30、1〜500）ごとに分けます。

補足
・ここでいう「行」は「ロケーション × 商品 × 出荷作業」の
  単位です。同じ棚の同じ商品でも、出荷作業が違えば別の行です。
・タスクの中の順番は、ロケーションの「並び順」→
  ロケーションコードの順です。
・ゾーンと並び順は、設定 → 倉庫・ロケーション で設定します。


■ 5. Pick List（ピッキングリスト）を印刷する

紙で作業するときや、作業内容を確認するときに使います。

1. 「Wave・ピッキング」一覧の「Pick List」、
   または Wave 詳細の「Pick List 印刷」を押します。
   新しいタブで「ピッキングリスト」が開きます。
2. 「印刷 / PDF保存」を押し、ブラウザの印刷画面で
   印刷または PDF 保存します。

【印刷される内容】
・見出し：Wave 番号、Wave 名、倉庫、作成日時、
  Wave 番号のバーコード（Code128）
・タスクごと（タスクごとに改ページ）：
  タスク番号とそのバーコード（Code128）
・表：チェック欄 / ロケーション（ゾーン）/ SKU・商品名 /
  数量 / 出荷番号（F- で始まる出荷作業番号）
  同じタスク内の同じロケーション・同じ商品は、
  数量を合計して 1 行で表示します。
・合計個数と行数、作業者・開始・終了の記入欄

【注意】
・お客様の氏名・住所などの個人情報は印刷されません。
・紙にチェックを付けるだけでは、在庫や進捗に反映されません。
  実績は、スマホの Pick 画面またはハンディスキャナで
  記録してください（リストにも同じ注意が印刷されます）。
・Pick List は配送会社の送り状ではありません。
・Wave 番号は、画面上部の検索欄に入力して検索することも
  できます。


■ 6. 作業の割り当て

通常は、作業者がスマホの「未担当のタスク」から
「このタスクを開始」を押して、自分で担当します。
同時に押した場合も担当できるのは 1 人だけで、
もう 1 人には「このタスクは ○○ が担当中です」と表示されます。
管理者は、次の方法でタスクを割り当てることもできます。

【Wave 詳細から割り当てる】
1. Wave 詳細の「Pick タスク」欄で、対象のタスクの
   「割当」を押します。
2. 「作業者」を選び、「割り当てる」を押します。
   すでに担当者がいる場合は付け替えになります
   （監査ログに記録されます）。
・「担当解除」を押すと担当者が外れます。
  ピック済みの数量はそのまま残り、
  別の人が続きから作業できます。
・選べる作業者は、Pick の権限を持つ人
  （Owner / Operations Manager / Picker）です。
  担当倉庫が限定されている作業者を、範囲外の倉庫の
  タスクに割り当てようとするとエラーになります。
・PC から「ピック画面」を押すと、スマホと同じ Pick 画面を
  開けます（Pick の権限がある場合）。

【作業割当 画面】
メニュー「作業割当」では、進行中の Pick タスク・梱包・
例外対応の担当者を一覧で確認し、割当・付け替え・解除が
できます。「倉庫」で絞り込めます。
・担当者ごとの現在の作業
  作業者ごとの Pick タスク・梱包・例外対応の件数です。
  現在の状況を見るためのもので、作業者の評価や
  ランキングには使いません。
・Pick タスク（N）
  タスク、Wave、倉庫・ゾーン、進捗、担当を表示します。
  担当の期限が切れていると「期限切れ」と表示されます。
  未担当は「割当」、担当ありは「付け替え」と「解除」。
  割り当てる作業者は「作業者（この倉庫の担当者のみ）」から
  選びます。
・梱包中（N）
  梱包中の作業と「中止」（「Packing Station.txt」参照）
・例外対応（未解決 N）
  例外ごとに担当者を選べます。

【Wave のタスクをまとめて 1 人に割り当てる】
1. Wave 詳細の「Pick タスク」欄の見出しにある
   「まとめて割り当て」を押します。
   未着手・作業中のタスクがあるときに表示されます。
2. 「W-000012 のタスクをまとめて割り当て」の画面で、
   「作業者」を選びます。
3. 「未担当のタスクだけ（外すと担当中のタスクも付け替えます）」
   は、初期状態でチェックが入っています。
   チェックを外すと、担当者がいるタスクも、選んだ作業者に
   付け替えます。
4. 「割り当てる」を押します。
   「N 件のタスクを割り当てました」と表示されます。
・対象は、その Wave の未完了（未着手・作業中）のタスクです。
・監査ログに「Wave の担当を割当」と記録されます。
・担当倉庫が限定されている作業者を、範囲外の倉庫の Wave に
  割り当てようとするとエラーになります。

【担当の期限（タイムアウト）】
・担当には期限があります。初期値は 30 分で、
  設定 → 組織・運用設定 の「作業の担当タイムアウト（分）」
  （5〜480 分）で変更できます。
・作業者が読取をするたびに、期限は延長されます。
・期限が切れたタスクは、スマホの「未担当のタスク」に表示され、
  他の作業者が「このタスクを開始」で続きから作業できます。
  ピック済みの数量は保持されます。
・期限切れの担当は、自動処理（おおむね 1 分ごと）で外れ、
  監査ログに「Pick タスクの期限切れ解放」と記録されます。
・管理者が割り当てた場合も同じ期限が付きます。
  割り当てられた人が期限内に読取を始めないと、
  割当は自動で外れます。
・Wave 詳細の「担当」欄に、期限の日時が表示されます。
・担当が別の人に移った後、元の担当者の端末に残っていた
  未同期の読取は、送信時にサーバーで拒否されます。


■ 7. Short（現物不足）の処理

【Short が報告されると】
作業者がスマホで「棚にない（Short）」を報告すると、
システムが自動で次の処理をします。
・その行の残り数量を「Short」として記録します。
  理由は「現物なし / 破損 / Location違い / 数量不足 /
  その他」から選ばれます。
・Short 分の引当を解放します。
・在庫数（OnHand）は減らさず、その数量を「調査中」に移します。
  調査中の数量は引当可能数（Available）に含まれないため、
  他の注文に引き当てられることはありません。
・例外キューに、出荷作業ごとの「Short Pick」（注文側）と、
  ロケーションの在庫ごとの「在庫不整合」（在庫側）の
  例外を作ります（重要度 高）。
・注文は自動でキャンセルされません。
  注文の状態は「一部引当」などに戻ります。
・Short が残っている出荷作業は、Short を解決するまで
  梱包を始められません。

【注文側：Short を解決する】
操作できる人：Owner / Operations Manager

1. メニュー「Fulfillment」で「絞り込み」を「Short あり」に
   します。例外キューの「Short Pick」の詳細にある
   「（Fulfillment 一覧で対応）」からも移動できます。
2. 対象の出荷作業の「Short を解決」を押します。
3. 次のどちらかを選び、「実行」を押します。
   ・「別の倉庫（または同じ倉庫の別ロケーション）から
     再割当する」
     「再割当する倉庫」を選びます。その倉庫の在庫で引当し、
     新しい出荷作業（Wave待ち）が作られます。
     在庫が足りない分は未引当のまま残ります。
     結果は「Short N 個のうち N 個を再割当しました」と
     表示されます。
   ・「バックログへ戻す（入荷後などに改めて引当）」
     Short 分を出荷作業から外し、注文の未引当分に戻します。
     入荷後などに、あらためて引当してください。

補足
・どちらの場合も注文の数量は変わらず、
  注文はキャンセルされません。
・ピック済みの商品は、元の出荷作業で梱包・出荷できます
  （分割出荷）。Short 分を外した結果、商品が 1 つも残らない
  出荷作業は、キャンセル扱いになります。
・実行すると「Short Pick」の例外は自動で解決になります。
・お客様と合意して注文数量を減らす場合は、注文画面の
  「明細取消」で行います。システムが自動で減らすことは
  ありません。

【在庫側：調査中の在庫を確認する】
1. 例外キューで「在庫不整合」の例外を開きます。
2. 棚を確認し、「調査中の在庫」欄に数量を入れて
   次のどちらかを押します。
   ・見つかった場合：「見つかった（引当可能に戻す）」
   ・見つからない場合：「紛失確定（在庫を減らす）」
   （在庫の調整権限が必要です：Owner / Operations Manager）
3. 処理が終わったら、例外の「解決」を押し、
   解決方法（例: 在庫を調整）を選んで解決にします。
メニュー「在庫・商品」の「在庫」タブにある
「調査中を解消」からも、同じ処理ができます。


■ 8. ピック実績の訂正

・ピック済みの数量を直接書き換えることはできません。
  間違えてピックしたときは、スマホの Pick 画面の
  「読取履歴・訂正」で「1個取消」を押し、
  マイナスの訂正記録を追加します。元の記録は消えません。
・訂正すると、その行は未完了に戻ります。
  完了していたタスクは「作業中」に戻ります。
・訂正できるのは、その出荷作業の梱包が始まる前までです。
  梱包が始まっていると「梱包が始まった Fulfillment の
  ピック実績は訂正できません」と表示されます。
・訂正はオンラインのときだけできます。
  監査ログに「Pick を訂正」と記録されます。
・訂正は、そのタスクの担当者（または管理者）が行います。


■ 9. Wave の取消

操作できる人：Owner / Operations Manager

【取消できない場合】
・梱包が始まった出荷作業を含む Wave
・未解決の Short がある Wave
  「未解決の Short Pick があります。先に Fulfillment 画面の
  「Short を解決」で処理してください」と表示されます。
  7 章の手順で Short を解決してから取消してください。

【手順】
1. Wave 詳細の「Wave を取消」を押します。
   完了・取消済みの Wave には表示されません。
2. 理由を入力し、「取消する」を押します。
3. ピック済みの商品がある場合は、
   「ピック済みの商品があります。取消すると棚戻しの例外が
   作成されます。本当に取消しますか？」と表示されます。
   内容を確認し、「棚戻しを伴って取消」を押します。

【取消した結果】
・Wave は「取消」になり、未完了のタスクも「取消」になります。
・出荷作業は「Wave待ち」に戻り、新しい Wave に入れ直せます
  （引当はそのまま残ります）。
・ピック済みの数量は訂正記録で 0 に戻り、例外キューに
  「キャンセル棚戻し」の例外が作られます。
  例外に表示される商品・数量・ロケーションに従って、
  商品を棚に戻してください。
・監査ログに「Wave を取消」と記録されます。


■ 10. 進捗を確認する

・「Wave・ピッキング」一覧
  状態のタブ（すべて / 未着手 / ピッキング中 / ピック完了 /
  完了 / 取消）で絞り込めます。
  進捗バーと、ピック済みの数 / 必要な数、Short があれば
  「Short N」が表示されます。約 15 秒ごとに自動更新されます。
・Wave の状態の流れ
  未着手 → ピッキング中 → ピック完了（全タスク完了）→
  完了（すべての出荷作業が梱包済・出荷済・キャンセルのいずれか）
・Wave 詳細
  「Pick タスク」欄に、タスクごとの状態（未着手 / 作業中 /
  完了 / 取消）、担当者と期限、進捗、Short が表示されます。
  「含まれる Fulfillment（作成時に固定）」欄には、
  出荷作業ごとの状態・保留・Short が表示されます。
  途中でキャンセルされた出荷作業は薄く表示され、
  「除外: 理由」が付きます。約 10 秒ごとに自動更新されます。
・作業割当 画面
  誰がどのタスクを担当しているかを確認できます
  （約 20 秒ごとに自動更新）。
・ホーム
  「Wave 待ち」「ピッキング中」「梱包待ち・梱包中」
  「出荷待ち」「出荷期限超過」などの件数が表示されます。
・KPI
  「品質（誤出荷防止）」に「Pick 誤 scan 率」
  「Short Pick 率」「Short Pick 件数」などが表示されます。


■ 11. 権限（初期のロール）

・Wave の作成・取消、タスクの割当・解除：
  Owner / Operations Manager
・Short の解決（Fulfillment 画面）：
  Owner / Operations Manager
・Wave と Pick List の閲覧：
  Owner / Operations Manager / Picker
・ピッキング（Pick 画面）：
  Owner / Operations Manager / Picker
・担当倉庫が限定されている人は、その倉庫の Wave と
  タスクだけを表示・担当できます。


■ 12. 送り状・印刷・動作確認について

・CommerceOps は配送会社の公式送り状を作成しません。
  Pick List・注文識別コード・納品書・出荷作業票は、
  いずれも送り状ではありません。
  送り状は各配送会社のシステムで発行し、追跡番号を
  CommerceOps に入力するか CSV で取り込みます
  （「出荷と分割発送.txt」参照）。
  配送会社のシステムとの自動連携はありません。
・印刷はブラウザの印刷機能（紙 / PDF 保存）を使います。
  お使いのプリンタでの印刷結果（用紙・余白・バーコードの
  読みやすさ）は、導入前に確認してください。
・自動テストは Chromium のデバイスエミュレーションで
  実施しています。実機（iPhone / Android / iPad）、
  ハンディスキャナ、プリンタでの動作確認は、
  導入前にお客様の環境で行ってください。
