- ☐ 商品・在庫の CSV 取込、JAN の先頭 0 が Excel で消えないこと（buyer-docs/CSVテンプレート/CSVテンプレートの説明.txt）

## 5. サーバー・運用（docs/DEPLOY.md・OPERATIONS.md）
- ☐ ホスティング・DB の選定と契約（料金・リージョン・データ所在・SLA は契約前に公式ページで確認。docs/OPERATING_COSTS.md は 2026-09-30 時点の調査）
- ☐ DB ユーザーが NOSUPERUSER / NOBYPASSRLS（本番ではアプリが起動を拒否する）
- ☐ HTTPS（リバースプロキシ / PaaS）、`TRUST_PROXY`、`APP_BASE_URL`、`COOKIE_SECURE=true`、`ALLOW_SIGNUP=false`
- ☐ 秘密情報（DB パスワード等）を環境変数で渡し、リポジトリ・チャットに残さない
- ☐ Owner の作成 → 初回ログイン → 「パスワード変更」
- ☐ Job worker が動いていること（自動引当・Pick の担当期限・保持期限・**統計情報の更新**）: `RUN_WORKER=true` または `node dist/worker.js`
- ☐ バックアップ: DB 全体（マネージドの自動バックアップ / PITR または pg_dump）+ 組織単位（画面 / backup-cli）を別の場所へ。**復元のリハーサル**（画面から新しい組織として復元、CLI で空の環境へ）
- ☐ 監視: `/readyz`、エラーログ、DB 容量（1 注文あたり約 22.6KB の実測で見積もり）、毎日の整合性チェック（`integrity-cli --all`）
- ☐ ログインの回数制限（`LOGIN_RATE_LIMIT_MAX`、15 分 20 回 / IP）が、同じ回線から大勢がログインする現場で足りるか
- ☐ アップデート手順（バックアップ → 更新 → マイグレーションは起動時に自動 → 整合性チェック）
- ☐ 性能: 購入者の環境・データ量で主要画面と 1 日の業務量を確認（開発時の実測値は保証値ではない）
